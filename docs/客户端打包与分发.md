# 客户端打包与分发（构建 vs 安装）

> 状态：备忘 ｜ 作者：dmql ｜ 更新：2026-09-25
> 关联：`客户端-Tauri壳-开发流程.md`（壳构建机制）、`wireframes/index.html`（架构分层）

## 一句话结论

> **开发环境麻烦是开发者一次性的事；最终用户拿到安装包双击即用，零配置。**
> 以后发版频繁时，用 CI（GitHub Actions）在云端自动构建，本地连 VS/SDK/Rust 都不用配。

## 两个完全不同的阶段

### 阶段 1 · 开发者构建安装包（只有开发者/CI 需要环境）

```
开发者机器（或 CI 云端）
  ├── VS 2022 + Windows SDK（VC Tools + Windows10SDK.19041）  ← 一次性
  ├── Rust（rustup default stable-msvc）
  ├── pnpm install
  └── tauri build
        │
        ▼
  产出：OsteosomeSetup.exe（或 .msi）
```

开发者机器需要完整工具链；**每次发版只需 `tauri build` 一次**。

### 阶段 2 · 最终用户安装（用户零门槛）

```
用户机器
  └── 双击 OsteosomeSetup.exe
        │
        ▼
  自动安装：壳(带前端) + 运行时（WebView2 自动检测/安装）
  └── 开箱即用，不需要装 Rust / VS / SDK / Node
```

Tauri 构建的安装包**自带所有运行时依赖**，用户无需任何开发环境。

## 用户/开发者需求对照

| 谁 | 需要什么 | 频率 |
|---|---|---|
| **最终用户** | 无 | 安装包双击即用 |
| **开发者（本地）** | Rust + VS + SDK | **只需配一次** |
| **CI（GitHub Actions，可选）** | 云端自动装好环境构建 | 每次发版自动跑 |

## 建议：发版频繁后用 CI 自动化

本地配环境只在**首次**需要。若发版变频繁，改用 **GitHub Actions** 在云端干净的
Windows 环境自动装 VS + SDK + Rust 构建，本地甚至不需要这套环境：

```yaml
# .github/workflows/build.yml（示意，后续落地）
- uses: dtolnay/rust-toolchain@stable
- uses: swatinem/rust-cache@v2
- run: pnpm install && pnpm build
- run: pnpm --filter @osteosome/tauri-app tauri build
- uses: actions/upload-artifact@v4   # 上传安装包
```

> 决策：CI 自动构建**暂不落地**，等开发到一定程度再上。

## 本地首配环境清单（Windows）

缺 Windows SDK 时的典型报错：`LNK1181: 无法打开输入文件 kernel32.lib`

1. **Rust**：`winget install Rustlang.Rustup` → `rustup default stable-msvc`
2. **Visual Studio 2022**（Visual Studio Installer → 修改 Community）勾选：
   - **使用 C++ 的桌面开发** → `Microsoft.VisualStudio.Component.VC.Tools.x86.x64`
   - **Windows 10 SDK** → `Microsoft.VisualStudio.Component.Windows10SDK.19041`
3. 装完跑 `.\start-client.cmd`（脚本已内置 `vswhere → vcvarsall` 自动注入 MSVC 环境）
