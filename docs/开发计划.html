开发计划 · 对话界面重构

减法 · 插件聚合 · 8 步
一句话：先减法（10 个服务 → 5），再修缺陷与拆组件（3 个盒子），最后做插件聚合。 前 2 天就有可见收益：进程数减半、启动变快、provider 一个不少。总计 8 天。

1未提交改动（P7 工具循环）
8计划天数

服务hello · session · loop · llm · llm-provider-{openai, openrouter, deepseek, anthropic} · credentials · llm-retry
组件10 个，其中 widget.llm-chat = 消息区 + 输入框焊在一起
已知缺陷 ① 思考流泄漏进正文（主位 isDelta 不看 blockType） ② 插件表硬编码在前端 ③ setEnabled 不真停服务 ④ hello 是纯演示

目标（定案）

界面3 个组件：session-list / chat-timeline / chat-composer，默认预设拼成正常 agent 对话界面
服务按功能：session / loop（编排）/ llm（模型接入）+ 能力位
provider一个通用 openai 兼容实现 + 厂商预设表（数据）；加厂商 = 加一行，不加代码不加进程
Core进程 + 总线 + 桥 + 凭证 store，零业务知识
插件聚合：一组服务 + 一组组件 + 依赖；Core 扫 plugins/*/plugin.json

明确不做：窄窗降级、代码语法高亮库、工具跨进程化、审批 listener、MCP 接入、上下文压缩、整体转 pi。

S1减法线 通用 provider：多实例 + 厂商预设表 ★核心1.5 天
为什么先做
  • 做完才能删包，且删包前用户不掉任何 provider
