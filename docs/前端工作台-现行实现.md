# 前端工作台：现行实现

> 本文档以当前仓库代码为准，更新于 2026-09-25。
>
> 现行工作台不是“一个 dockview 面板 = 一个 Pane 组件”，而是两层布局：
>
> ```text
> MainLayout
> └─ DockviewLayout                         外层：Panel 的停靠、拆分、比例、序列化
>    └─ PanelContainer                      内层：Widget 的自由拖动、缩放、吸附
>       └─ Widget component                  最小业务单元
> ```
>
> `dockview` 和 `vue-movable-box` 解决的问题不同，不能互相替代。

## 1. 实际技术栈

当前 `client/package.json` 的关键依赖：

| 依赖 | 实际职责 |
|---|---|
| `vue@3.5.x` | 组件和响应式运行时 |
| `dockview-vue` / `dockview-core` | 外层面板布局：Panel 停靠、拆分、比例、原生 tab、序列化 |
| `vue-movable-box@3.5.x` | Panel 内部组件盒子的拖动、缩放、层级和吸附 |
| `pinia` | 工作台状态、布局快照、服务状态 |
| `vue-router` | 主窗口和独立 Panel 窗口路由 |
| `vite` / `vue-tsc` | 开发服务器和生产构建 |

`client/src/main.ts` 必须引入两套布局的样式：

```ts
import 'dockview-vue/dist/styles/dockview.css'
import 'vue-movable-box/style.css'
```

## 2. 两层布局模型

### 2.1 外层：dockview 管理 Panel

入口是 `client/src/layout/DockviewLayout.vue`。

`DockviewVue` 的 `components` 当前只注册一个组件：

```ts
const components = { panel: PanelContainer }
```

也就是说，当前所有 dockview 面板都使用 `component: 'panel'`，由 `PanelContainer.vue` 承载 Widget，而不是直接把每个业务 Pane 注册成 dockview 组件。

外层负责：

- Panel 创建、关闭、停靠、拆分和调整比例；
- Panel 的原生 tab；
- `api.toJSON()` / `api.fromJSON()` 布局快照；
- `onDidLayoutChange` 后把外层快照交给 `layout.store`；
- 编辑 / 运行模式：运行模式隐藏组头并锁定拖拽；
- Panel 独立窗口入口。

当前外层状态在 `client/src/layout/layout.store.ts`：

```ts
{
  mode: 'edit' | 'runtime',
  snapshot: SerializedDockview | null,
  api: DockviewApi | null,
  hydrated: boolean,
  saving: boolean,
  lastError: string | null,
}
```

`SerializedDockview` 是外层布局的真源，保存到 `/api/preferences`。布局损坏时，`bootstrap()` 会丢弃快照，使用默认布局，并记录用户可读错误。

### 2.2 内层：vue-movable-box 管理 Widget

入口是 `client/src/panes/PanelContainer.vue`。

每个 Widget 会被渲染成一个 `MovableBox`：

```vue
<MovableBox
  v-for="widget in visible"
  v-model="widget.rect"
  drag-handle=".panel-boxes__header"
  :snap-to-elements="true"
  :snap-targets="snapTargets"
  @drag-stop="persist"
  @resize-stop="persist"
/>
```

每个 Widget 的几何数据是：

```ts
type MovableBoxRect = {
  left: number
  top: number
  width: number
  height: number
  zIndex: number
}
```

这些数据保存在外层 Panel 的 `params.layout[widgetId]` 中。拖动或缩放结束后，`PanelContainer` 调用：

1. `panel.api.updateParameters({ widgets, layout })` 更新当前 Panel 参数；
2. 派发 `osteosome:panel-layout` 事件；
3. `DockviewLayout` 收到事件后调用 `api.toJSON()`；
4. `layout.store.updateLayout()` 防抖保存到 `/api/preferences`。

因此，Widget 的位置不是另一套独立的全局布局，而是嵌入 dockview Panel 快照中的 `params.layout`。

### 2.3 默认 Widget 布局

没有已保存布局时，`client/src/panes/default-layout.ts` 创建一个 `panel.main`，并把 `defaultWidgetIds()` 返回的所有 Widget 放进去。

当前内置 Widget：

- `widget.service-status`
- `widget.hello-command`

Widget 定义由 `client/src/widgets/registry.ts` 通过：

```ts
import.meta.glob('./*/*-widget.vue', { eager: true })
```

自动发现。Widget 的最小契约是：

```ts
export interface WidgetDefinition {
  id: string
  title: string
  component: () => Promise<{ default: Component }>
}
```

开发新 Widget 时，文件放在 `client/src/widgets/<group>/`，文件名以 `-widget.vue` 结尾，并导出 `defineWidget({ id, title, component })`。

## 3. 运行时数据流

```text
用户拖动 / 缩放 Widget
        │
        ▼
PanelContainer
  updateParameters(params.widgets, params.layout)
        │  window event: osteosome:panel-layout
        ▼
DockviewLayout
  api.toJSON()
        │
        ▼
layout.store.updateLayout(snapshot)
        │  500ms debounce
        ▼
/api/preferences
```

外层 Panel 停靠、拆分、调整比例时：

```text
Dockview api.onDidLayoutChange
        │
        ▼
layout.store.updateLayout(api.toJSON())
        │
        ▼
/api/preferences
```

独立窗口不会复制业务数据。`window-manager.openPanelWindow(panelId, widgetIds)` 只打开：

```text
#/pane/:panelId?w=widgetA,widgetB
```

`PanelHost.vue` 读取 `id` 和 `widgets`，复用同一个 `PanelContainer`。Widget 内的数据仍通过 Core 的 SSE / command 链路获取。

## 4. 操作语义

| 操作 | 外层 dockview | 内层 vue-movable-box |
|---|---|---|
| 新建内容 | TopBar 新建 Panel；Panel 内添加 Widget | — |
| 停靠 / 拆分 | 支持，拖动 dockview Panel 或分隔条 | — |
| 调整 Panel 比例 | 支持 | — |
| 拖动 Widget | 不负责 | 支持，拖动标题栏 |
| 缩放 Widget | 不负责 | 支持，8 向缩放 |
| Widget 吸附 | 不负责 | 支持，`snap-to-elements` |
| 布局持久化 | Panel 结构、Panel 参数、Widget 几何一起进入 `SerializedDockview` | `params.layout[widgetId]` 保存几何 |
| 独立窗口 | `PanelHeaderActions` 调用 `openPanelWindow` | 传入 Widget id 列表 |

注意：Widget 的拖动手柄是 `.panel-boxes__header`，不是 Widget 内容区域。Widget 内容的滚动和交互因此不会被拖拽逻辑意外接管。

## 5. 组件职责边界

```text
DockviewLayout.vue
  └── 负责外层 dockview 生命周期、布局事件和模式

PanelContainer.vue
  └── 负责 Panel 内 Widget 盒子的创建、拖动、缩放、吸附和几何持久化

PanelHeaderActions.vue
  └── 负责重置、拉出独立窗、关闭 Panel

PanelTab.vue
  └── 负责自定义 dockview Panel tab 的标题和激活态

PanelHost.vue
  └── 负责独立窗口壳，不重复创建 dockview 外层

widgets/registry.ts
  └── 负责 Widget 定义发现和异步组件映射

layout.store.ts
  └── 负责外层 dockview 快照、偏好持久化和 Panel/Widget 操作
```

`PaneView.vue`、`PaneFrame.vue` 和 `layout.model.ts` 仍可能作为 P1b 兼容代码存在，但不是当前主工作台的渲染链路。后续维护应优先修改 `DockviewLayout.vue`、`PanelContainer.vue` 和 `layout.store.ts`，不要根据这些兼容文件的旧接口继续扩展主链路。

## 6. 新增 Widget 的最小步骤

1. 在 `client/src/widgets/<group>/` 新建 `xxx-widget.vue`；
2. 用 `defineWidget` 导出 `id`、`title` 和异步 `component`；
3. 在 `registry.ts` 的 glob 目录下放置文件，Vite 会自动发现；
4. 打开 TopBar 的“添加组件”，将 Widget 加入当前 Panel；
5. 通过 `panel.api.updateParameters()` 更新 `widgets` 和 `layout`；
6. 拖动或缩放后验证刷新页面能从 `/api/preferences` 恢复。

Widget 业务逻辑仍遵守 Core SDK 约定：

- 事件使用 `useEventBus()`；
- 命令使用 `useCommand()`；
- 不在 Widget 内直接维护第二套 SSE 连接；
- 不直接绕过 Core 调用业务 API。
