# P2 详细计划 · 最小 LLM 对话（能力位拆分 · 六插件实现）

> 修订：2026-09-28 **能力位拆分定案**（替代 2026-09-23 旧版「DSH 接缝三角·单 provider 实现」）。
> 旧版把接缝三角（`LlmAdapter` / `Registry` / `StreamChunk`）+ 凭证 resolver + retry 声明全部塞进 `services/llm` 单服务进程内；**新版按 OST 能力位思想把 LLM 拆成 6 个独立服务插件**——每个能力位一个进程，「存在性由插件决定」：装 provider 插件 → 该 provider 存在；卸掉 → 从系统消失（`unsupported_provider`）。dsh 是参照系不是目标（其 9 包是进程内 npm 包拆分），详见 [`LLM能力位拆分设计.md`](./LLM能力位拆分设计.md)。
> 阶段总量约 **1.5 周**（6 服务 + 2 Widget + 契约上移）。

---

## 0. 目标与范围

### 0.1 目标

- 跑通「前端 chat Widget → `/api/command` → llm 主服务 → provider 服务 → 上游（deepseek/openrouter/其他 openai 兼容）→ 流式 chunk 回前端」的整条链路。
- **能力位先于实现**：把 LLM 拆成 6 个能力位插件（`llm` / 3×`llm-provider-*` / `credentials` / `llm-retry`），每个独立服务进程，走总线注册与流转；P4 只做「更多 provider + 凭证 store + retry 执行器 + 管理 Pane」，不重写骨架。

### 0.2 范围内（In Scope）

- `shared/src/llm/`：`StreamChunk` 中立流协议 + `readSseJson` SSE 归一 + `ChatMessage` / `ProviderDescriptor` 类型（从 `services/llm/src/` 上移为唯一真相源）。
- `shared/src/events.ts`：只增 `llm.provider.*` / `credentials.*` / `llm.metrics.*` 契约（见 §3 事件表）。
- `services/credentials/`：凭证能力位（v1 `env:<VAR>`；预留 `core:` P4）。
- `services/llm/`：能力主位重写——provider 路由表 + chunk 翻译对外事件 + cancel 转发，**不 import 任何 provider 实现**。
- `services/llm-provider-deepseek/` + `services/llm-provider-openrouter/`：openai 兼容 wire 的 provider 能力位。
- `services/llm-provider-openai/`：通用 openai 兼容 provider 能力位（baseURL 可配，deepseek / openrouter / 其他一键接入；openrouter 走既有 baseURL 分支）。
> **2026-09-28 修订（WS-6 改向）**：opencode 不做（另有安排），WS-6 改做**通用 openai 兼容 provider**——与 WS-5 的 deepseek/openrouter 同构（同一 StreamChunk wire 翻译 / 错误码化），差异仅为「baseURL 可配置 + header 扩展」，对齐设计文档「P2 阶段波动：先切 openai 兼容基类再换 baseURL」。
- `services/llm-retry/`：retry 声明消费 + usage 记账（P2 只声明不执行）。
- 前端 `widgets/llm-chat/` + `widgets/llm-providers/`：发问/停止 + provider 状态。

### 0.3 范围外（Out of Scope）

- ❌ 凭证存储 / 加解密 / 设置 Pane —— P4（`credentials` 服务落 `core:<id>` kind + `dataDir/credentials.json`）。
- ❌ retry 执行器（真重试）—— P4（`llm-retry` 读 P2 声明执行）。
- ❌ 模型目录 `listModels()` —— P4。
- ❌ Session / Loop / 多轮历史 —— P3。
- ❌ 工具调用（tool-call 块）解析执行 —— P7；P2 只透传层**识别并降级** tool-call 块（跳过不渲染，不报错）。
- ❌ reasoning 块渲染 —— P4/P7 视需要新增 `llm.block.*` 事件（只增不改）。
- ❌ 凭证值进 SSE / 前端 —— 永远不进（`credentials.resolved` 只在服务间总线传播）。

## 3. 接口定案

### 3.1 StreamChunk → 对外事件映射（主位翻译层）

```ts
type StreamChunk =
  | { kind: 'block-start'; id: string; blockType: 'text' | 'reasoning' | 'tool_call'; index: number }
  | { kind: 'delta'; id: string; blockType: 'text' | 'reasoning'; text: string }
  | { kind: 'tool-arg-delta'; id: string; blockType: 'tool_call'; name: string | null; arguments: string }
  | { kind: 'block-end'; id: string; blockType: 'text' | 'reasoning' | 'tool_call' }
  | { kind: 'finish'; finishReason: 'stop' | 'length' | 'content_filter' | 'tool_calls' | 'error'; usage?; error?: StreamError }
```

- `{ kind: 'delta', blockType: 'text' }` → `llm.token.streamed { requestId, token, index }`（index = 请求内文本 delta 服务侧递增序号）
- `{ kind: 'finish', finishReason: 'stop'|'length'|'content_filter'|'tool_calls' }` → `llm.request.finished { requestId, finishReason, usage? }`
- `{ kind: 'finish', finishReason: 'error', error }` → `llm.request.failed { requestId, error }`
- `reasoning` / `tool_call` / `block-start` / `block-end` **不产生对外事件**（P2 识别降级：跳过不渲染不报错）
- **取消**：`aborted` 不进 finishReason 枚举，取消统一走 `finish{ stop }`（成功取消不留痕）

### 3.2 ProviderDescriptor（provider 服务注册时发布）

```ts
interface ProviderDescriptor {
  provider: string        // 'deepseek' | 'openrouter' | 'openai'
  defaultModel: string
  credentialRef: string   // 'env:DEEPSEEK_API_KEY' 等；P4 支持 'core:<id>'
  retryPolicy: RetryPolicy // { maxAttempts, baseDelayMs, backoff, retryableCodes }
}
```

### 3.3 错误码（全链路不再出现供应商字符串匹配）

`unauthorized`（401/403）｜ `rate_limited`（429，瞬态）｜ `server_error`（5xx，瞬态）｜ `network`（fetch 异常/超时，瞬态）｜ `invalid_request`（400/wire 畸形）｜ `unsupported_provider`（主位路由缺失）｜ `missing_credential`（凭证解析失败）

### 3.4 取消语义

`llm.cancel { requestId }` → 主位转发 `llm.provider.cancel` → provider `signal.abort()` → 上游断开 → 发 `finish{ stop }` → 主位发 `llm.request.finished { finishReason: 'stop' }`。**取消不是失败**：前端收到 finished 收起 Spinner，不显示错误。

## 6. 风险与决策

| 主题 | 决策 / 规避 |
|---|---|
| **服务进程数量膨胀** | 6 进程可接受；P4 若 provider 增多引入「provider 容器进程」（共享进程，保持能力位语义） |
| **接缝过度设计** | 契约上移 shared 是唯一真相源；provider 服务只依赖 shared 协议，不相互 import |
| **凭证值进总线** | `credentials.resolved` 的 apiKey 只在服务间总线传播，永不进 SSE/前端；P4 落 core store 后值甚至不出 credentials 服务 |
| **通用 openai 兼容接入** | WS-6 提供 `llm-provider-openai`（baseURL 可配），对主位透明；`llm-provider-opencode` 不做（另有安排） |
| **retry 空转** | retry 在 P2 只声明 + 记账，不执行——避免半吊子重试造成重复请求；执行器 P4 装备 |
| **崩溃恢复** | 交给 Core 进程管理（P1a）：kill provider → 拉起 → 重新 registered；请求级重试 P4 再做 |
| **事件 flood** | token 逐条发布 OK（RFC 既有契约）；若 P4 吞吐瓶颈，再以 `llm.block.*` 增量降频（只增不改），P2 不预建 |
| **P2 阶段波动** | 契约上移 + 6 服务 + 2 Widget 一次 PR 交付；如某 provider wire 探测超时，先切 openai 兼容基类再换 baseURL |
