# P4 详细计划 · 多模型服务商管理（凭证 seam + 设置 Pane）

> 修订：2026-09-23 评估定案。原 P4（多 provider 配置 Pane）**扩展 +30~50%**：新增 core 凭证 seam（`core/src/credentials/`）、设置 Pane 套件（LLM / UI / 高级）、模型目录 `listModels()`、retry 执行器；P1b 延后的主题系统与 i18n 在本阶段补齐。工作量 **+2~3 天，阶段总量约 1.5-2 周**。P2 的接缝三角（**LlmAdapter / Registry / StreamChunk**）+ 两个声明式接缝（**凭证引用 / retry 声明**）在本阶段**只加实现与执行器，不改骨架**。

---

## 0. 目标与范围

### 0.1 目标

- 新增服务商不再手改单函数：openai / anthropic / openrouter 三个适配器**只注册不改核**（兑现 `ost-开发文档.md` §16 A组④ 五项契约对齐）。
- 凭证成为一等公民：明文只进 dataDir，**值永不进总线 / SSE**；前端只见掩码。
- 设置 Pane：provider 增删改查 + 凭证绑定 + 模型下拉 + 主题 / 语言 / 重试参数，全部走 ui 组件库。

### 0.2 范围内（In Scope）

- `core/src/credentials/` —— 凭证存储（`dataDir/credentials.json`）+ JSON-RPC 方法（`credentials.get/set/delete/list`）+ SSE `/api/credentials`（GET 掩码 / PUT / DELETE）。
- 前端**配置类操作统一走 SSE 端点**（与 `/api/credentials` 同规）：`/api/llm-config` GET/PUT（Core 经 **JSON-RPC `call('llm.config.get/set')` 转发**给 llm 服务——与 `credentials.get` 同通道、**不走 bus**，config 值不污染总线；真源仍在 llm 服务，见 §3.3 通道定案）。
- LLM 侧兑现 P2 接缝：
  - `credentials/resolver.ts` 接上 `core:<credentialId>` kind（经 SDK 走 core JSON-RPC，**不经总线**）；
  - `retry/engine.ts` —— 执行 P2 声明的 `RetryPolicy`（backoff + jitter + `retryableCodes`）。
- 三个新适配器：`adapter/openai.ts` / `adapter/anthropic.ts` / `adapter/openrouter.ts`；`StreamChunk` 块协议与 usage 归一化（disjoint 记账）。
- 模型目录：`llm.models.list` → `llm.models.list.result`（`listModels()`：逐 provider 拉 `/models`，失败降级静态默认）。
- 设置 Pane 套件：`settings-pane` / `llm-settings` / `ui-settings` / `advanced-settings`。
- 主题系统（P1b 延后项）：`data-theme` 切换 + `tokens.css` 双主题完整；i18n（P1b 延后项）：`vue-i18n` + zh-CN / en。
- `format` 遗留处置：**删除**（新设计不引入 format 配置，兑现「兑现或删除」）。

### 0.3 范围外（Out of Scope）

- ❌ 系统 keychain / 加密存储（OS keyring 属 P8 远期评估；P4 明文 dataDir + 威胁模型说明，见 §6）。
- ❌ 会话 / Loop / 角色 / 技能 / MCP —— 各自阶段。
- ❌ 供应商 OAuth（Anthropic Console OAuth 旁路等）—— 后续按需，P4 只 apiKey。
- ❌ 跨 provider 请求级 failover / 负载均衡 —— retry 执行器只对单 provider 重试。
- ❌ 断流续传（流中断自动续写）—— P7+。
- ❌ 记账报表 / usage 聚合面板 —— 只落 `Message.usage`，不建报表。

## 2. 工作分解（WS-1 ~ WS-5）

### WS-1 · core 凭证 seam（2d）

- [ ] `core/src/credentials/store.ts` —— `dataDir/credentials.json`：
  - 结构 `{ [id]: { id, name, provider, kind: 'apiKey', value, createdAt, updatedAt } }`
  - 原子写（临时 + rename）；损坏 → 服务可启但凭证列表报错态（不崩 Core）
- [ ] `core/src/credentials/api.ts` —— `get(id)` / `maskedList()` / `set()` / `delete()`；**发事件只含 `{ id, name, provider }`，值不入 payload**
- [ ] JSON-RPC 方法：**只增不改**——P1a 方法集（`initialize` / `service.*` 等）原样不动，P4 仅**追加 `credentials.*` 命名空间**，四个新方法走同一 handler 表机制：`credentials.get`（返回原值，**只给服务进程**）/ `credentials.set` / `credentials.delete` / `credentials.list`（返回掩码）
- [ ] SSE `/api/credentials`：GET → 掩码列表；PUT → 写入；DELETE → 删除（前端通道，永不回原值）
- [ ] `core/src/sse-bridge/server.ts` —— **挂载新路由**：`/api/credentials`（credentials.ts handler）+ `/api/llm-config`（llm-config.ts handler）；沿用 P1a 路由表与 Origin 白名单
- [ ] 事件（只增不改）：`credential.saved` / `credential.deleted` —— payload `{ id, name, provider }`
- [ ] SDK `call(method, params)`：通用请求/响应配对（复用 P1a transport；handshake 已有雏形）
- [ ] **子绿灯**：store 单测（原子写 / 损坏降级）+ 值不进事件断言 + SSE 掩码回包断言 + 服务进程 `call('credentials.get')` 拿原值

### WS-2 · resolver 接 core + retry 执行器（1.5d）

- [ ] `credentials/resolver.ts` —— `core:<credentialId>` kind → `sdk.call('credentials.get', …)`；`env:` 维持（P2 兼容）。值只进 `LlmAdapterContext.apiKey` 内存，不落盘不进事件
- [ ] `retry/engine.ts` —— 执行 P2 的 `RetryPolicy`：
  - 判定：`error.code ∈ retryableCodes` 才重试；`maxAttempts` 上限；`baseDelayMs * 2^n + jitter`
  - 挂在 `adapter.stream` 外层：**首块到达前**的失败才重试；**首块已出 → 不重试，直接 `yield finish{ finishReason: 'error', error }` 上抛**（流中断不自动续，见 §6）
  - 参数可被 `serviceDataDir(dataDir,'llm')/config.json` 按 provider 覆盖（P2 默认值保底）
- [ ] **子绿灯**：engine 单测（429 退避重试到上限 / 401 立即失败 / 指数+jitter 窗口 / 配置覆盖生效 / **首块后失败 → finish{error} 直出且 attempts=1**）

### WS-3 · 三个新 provider + 模型目录（2d）

- [ ] `adapter/openai.ts` —— 官方 wire；usage `prompt_tokens/completion_tokens` → `Usage`
- [ ] `adapter/anthropic.ts` —— messages API；SSE `message_start/content_block_start/delta/stop` 事件 → `StreamChunk` 块协议；usage `input_tokens/output_tokens` → `Usage`（**disjoint 记账归一**）；`stop_reason` → finishReason
- [ ] `adapter/openrouter.ts` —— openai 兼容（baseURL `https://openrouter.ai/api/v1`）；headers `HTTP-Referer`/`X-Title` 可配
- [ ] registry 扩展 route 元数据：`{ provider, baseURL 默认, credentialProviderId, listModelsEndpoint, staticModels }`（P2 的 `list()` 返回即服务此处）
- [ ] `config.ts` —— `serviceDataDir(dataDir,'llm')/config.json`（provider 启用/默认 baseURL/model/credentialRef/retry 参数）；命令 `llm.config.get/set`（**仅 Core 经 `/api/llm-config` + JSON-RPC `call` 转发调用**，前端不直连 bus，llm manifest 不需 `subscribes`）→ 事件 `llm.config.changed`（value 不含凭证原值，只有 `credentialRef`）
- [ ] `model-catalog.ts` —— `llm.models.list { requestId, provider }` → `llm.models.list.result { requestId, models: string[] }`；逐 provider `GET {baseURL}/models`（anthropic 为 `/v1/models`），超时/失败 → `staticModels` 降级 + 结果带 `source: 'remote'|'static'`
- [ ] `format` 遗留确认删除（不引入 format 配置；§16「兑现或删除」→ 删除）
- [ ] **子绿灯**：三适配器对伪 SSE 的块协议翻译单测（多事件流、usage 归一、错误码化）+ config 往返 + listModels 降级

### WS-4 · 设置 Pane 套件 + 主题 / i18n（2d）

## 3. 接口定案（P4 补齐）

### 3.1 凭证数据与通道（值永不进总线）

| 通道 | 内容 | 谁可见 |
|---|---|---|
| `credentials.get`（JSON-RPC → SDK `call`） | 原值 | **仅服务进程**（llm 等） |
| `/api/credentials` GET（SSE 桥） | 掩码（如 `sk-***1234`） | 前端 |
| `/api/llm-config` GET / PUT（SSE 桥） | llm 配置（只含 `credentialRef`，无值） | 前端 |
| `credential.saved/deleted`（总线事件） | `{ id, name, provider }` | 全端（无值） |
| `LlmAdapterContext.apiKey` | 原值 | 仅 llm 进程内存 |

> **安全**：`/api/credentials` 与 `/api/llm-config` 均受 **P1a 全局 Origin 白名单**保护（`127.0.0.1:1420` / `localhost:1420` / 不带 Origin 头 / `Origin: null`，其余 403）——任意网页无法 PUT 凭证或改配置（二轮 review ⑦，P1a 已落地）。

**`PUT /api/credentials` body**（新建 / 更新）：

```ts
// 新建
{ id: string, name: string, provider: string, value: string }
// 更新（省略字段不变）
{ id: string, name?: string, value?: string }
// 响应
{ ok: true, id }
```

### 3.2 凭证 / 配置 JSON 形状

```ts
// {dataDir}/credentials.json                       # Core 自己的数据，落 dataDir 根（P1a §3.1 例外）
{ [id: string]: { id, name, provider, kind: 'apiKey', value, createdAt, updatedAt } }

// serviceDataDir(dataDir,'llm')/config.json        # = ${dataDir}/services/llm/config.json（服务规范路径）
{ providers: {
    deepseek:   { enabled, baseURL, defaultModel, credentialRef: 'core:<id>' | 'env:DEEPSEEK_API_KEY', retry?: RetryPolicy },
    openai:     { ... }, anthropic: { ... }, openrouter: { ... }
  }
}
```

### 3.3 模型目录命令

| 命令 | 订阅者 | 结果 topic |
|---|---|---|
| `llm.models.list { requestId, provider }` | llm | `llm.models.list.result { requestId, models: string[], source: 'remote'\|'static' }` |
| `llm.config.get` / `llm.config.set` | llm | `/api/llm-config` 响应 / 发布 `llm.config.changed` |

> **通道定案（三轮 review ②）**：
> - `llm.models.list` 走 **bus**——前端 `/api/command` → bus → llm 订阅处理 → `llm.models.list.result`（llm manifest 需 `subscribes` 该命令 topic）。
> - `llm.config.get/set` 走 **JSON-RPC**——Core 收 `/api/llm-config` 后 `sdk.call('llm.config.get/set')` **直调 llm 进程**，与 `credentials.get` 同通道、**不经 bus**（config 值不污染总线）；llm manifest **不需** `subscribes` 这两个 topic。写成功后 llm 仍**发布 `llm.config.changed`** 广播给前端刷新 UI。

### 3.4 事件契约（只增不改）

| Topic | 语义 | Payload |
|---|---|---|
| `credential.saved` | 凭证写入 | `{ id, name, provider }`（**无值**） |
| `credential.deleted` | 凭证删除 | `{ id }` |
| `llm.config.changed` | provider 配置变更 | `{ providers }`（只含 credentialRef，无值） |
| `llm.models.list.result` | 见 §3.3 | `{ requestId, models, source }` |

core JSON-RPC 方法集**只增不改**：P1a 方法不动，仅追加 `credentials.*` 命名空间四方法（`credentials.get` / `credentials.set` / `credentials.delete` / `credentials.list`；同步写入事件一并发布）。

### 3.5 §16 A组④ 五项契约对齐复核表

| 项 | 落点 | 阶段 |
|---|---|---|
| StreamChunk 块化（block-start/delta/block-end/finish + reasoning/tool-arg） | `adapter/types.ts` + `stream.ts`；**P2 定案名 `StreamChunk`**（RFC 原文 LLMChunk，全文统一前者） | P2 |
| `format` 兑现或删除 | **删除**，不引入 format 配置 | P2/P4 确认 |
| 字符串判 429 → 错误码化 | `StreamErrorCode`（P2 §3.3） | P2 |
| disjoint 记账（usage 归一 + 落 `Message.usage`） | 各适配器 → `Usage`；P3 `Message.usage` 已备 | P4 |
| 凭证 seam（按请求解析、值不落总线） | `core/src/credentials/` + resolver `core:` kind | P4 |
| 声明式 retry → 执行器 | `retry/policy.ts`（声明）→ `retry/engine.ts`（执行） | P2 → P4 |

## 6. 风险与决策

| 主题 | 决策 / 规避 |
|---|---|
| **明文凭证威胁模型** | P4 只存 `dataDir/credentials.json` 明文——**你已信任本机数据目录**（与会话 log 同级信任）；不引系统 keychain（P8 再评估 OS keyring / 加密）。红线：**值永不进总线/SSE/事件**，掩码是前端唯一视图 |
| **凭证读取通道** | 服务进程读原值走 core JSON-RPC（stdio），**不走 bus**——bus 全端可见，天然泄漏面；前端读走 SSE 掩码接口 |
| **retry 语义边界** | 执行器只对「首块前」失败重试（连接/鉴权/限流类）；**首块已出后失败 → 直接 `finish{ finishReason:'error' }` 上抛，不重试**；流中断不自动续写——续写涉及状态回放，归 P7+ |
| **anthropic wire 差异** | 不强行统一成 openai 兼容（会丢掉 block 边界）；差异在 `adapter/anthropic.ts` 内部消化，向上只吐 `StreamChunk` |
| **listModels 可用性** | 各家 `/models` 口径不一 → 结果带 `source` 标记 + `staticModels` 兜底，不让设置 Pane 转圈卡死 |
| **i18n 范围蔓延** | P4 只做 zh-CN / en 基础资源（设置 + 既有 ui 文案）；不做全量文案国际化，Pane 文案按需后补 |
| **配置归属** | provider 配置归 llm 服务（`serviceDataDir(dataDir,'llm')/config.json`），凭证归 core（`dataDir/credentials.json`），偏好归 SSE 桥（preferences）——不混文件，不跨进程写别人的数据 |

## 7. 开工顺序

```
P1a + P1b + P2 + P3 全绿
  └► WS-1 core 凭证 seam ─────────┐
  └► WS-3 三个 provider + 目录 ───┼─► WS-4 设置 Pane + 主题/i18n ──┐
      （可与 WS-1 并行，只要 LlmAdapter 契约不动）                 ├─► WS-5 收尾
```

- 每个 WS 单独 commit；WS-5 时整个 P4 一个 PR（含 §16 契约对齐复核）。
