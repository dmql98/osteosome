## 5. 踩过的坑（**交接必读**）

### 5.1 会静默出错的（最危险）

| 坑 | 症状 | 规矩 |
|---|---|---|
| **一个动作在两处生效** | 禁用插件后**重启 Core 它自己回来了**。单测全绿、冒烟 PASS，**只有重启才现形** | 任何「让某个东西不再运行」的动作，都要问一遍「重启后还在吗」，并把两个生效点写在同一处注释里 |
| **B 语义下「没有清单」= 零服务 = 应用不可用** | 差点 bricking app | 已加三态降级（`disabled` 不告警 / `missing-dir` `empty` 告警+全启）。**拆子步时先问「这几步之间有没有必须先做的关系」** |
| **纯事件驱动没有初始快照** | provider 在握手完成时就注册完了，页面之后才打开 → **永远显示「未连接」** | 已加 `llm.provider.reannounce`。任何「靠事件推导状态」的清单都要有主动对齐 |
| **独立窗口各有各的 pinia** | 主窗口 `bootstrap()` 对插件窗无效 → `enabled`/`uninstalled` 永远为空，**界面显示错但没有任何报错** | 「删掉一个看起来多余的调用」前，先问它在哪些执行上下文里被调用过 |
| **测试 mock 每个 topic 只存一个 handler** | 后订阅的顶掉先订阅的 → 症状像「事件机制坏了」 | **mock 的缺陷比被测代码的缺陷更难查** |
| **局部自洽、全局出错** | 本轮三条最咬人的坑都是这个形状，单测与冒烟都覆盖不到 | 「全绿」不等于「对」—— 必须问「**有没有哪条路径没人测过**」 |
| **清单声明与代码订阅会漂移** | 服务照常 `ready`、命令 202、**总线上零订阅者**，界面只是「没反应」，日志里只有 SDK 一行 `warn`（`busRequest` 吞了 `-32001`） | 已加 `core/tests/service-manifest-sync.test.ts` 扫源码比对 `service.json`；改 `service.json` 记得重启 Core（4.1 #7） |
| **`await send()` ≠ 结果到了** | `useCommand.send` 只等 HTTP 202，SSE 回音是另一条路。原 `finally { clearTimeout(timer) }` 紧跟 `await send()` → 8 秒兜底提前撤掉 → `probing` 永卡 true、`probe()` 恒 null | 兜底计时器必须活到**真正结算**为止；把「发出去」和「收到结果」当两件事 |
| **有反馈但没渲染 = 没反馈** | `useEndpointProbe` 明明返回了结果，`ProviderCatalog` 没有状态位 → 用户看到的就是「点了连接没反应」 | 写交互前先确认反馈那一环真的被渲染；别拿「数据有了」当成「用户看到了」 |

### 5.2 Vue SFC 的两个（都踩了两次）

| 坑 | 症状 | 规矩 |
|---|---|---|
| **`<script>` 之前的内容按 HTML 解析** | 文件头 JS 块注释里写 `<dl>` → 被当顶层标签 → `Element is missing end tag`，**错误位置不指向真因** | 说明注释一律写在 `<script>` **内部** |

### 5.3 工具与验证纪律

- **只看 `$LASTEXITCODE` 判定成败**；grep 仅用于定位，不能过滤错误后宣称通过（本项目曾因此连续三次报「绿」）
- **PowerShell 只用于只读检查/调用**。修改含反引号 / `${}` / 中文标点的文件一律用编辑工具 —— 本轮多次被它吃掉引号
- **`Get-Content` 在按 ANSI 解码中文时会少数约 120 行** —— 「行数配平」这类校验必须用 node 读字节
- **校验标签配平要覆盖全部标签**（本轮 26 类），且写完 HTML 改动后必查乱码字符（U+FFFD 替换字符）。注意**不要在文档里直接写那个替换字符举例** —— 否则自己的乱码检查永远报红
- **审计脚本自己也要被审计**：S8 的核对脚本用 `claimed.add(...arr)` 误报「llm/loop 未认领」，差点让我去改本来正确的清单（`Set.add` 只接受一个参数）
- **报错位置不等于出错位置**（见 5.2）
- **`vi.useFakeTimers()` 默认连 `setImmediate` 一起伪造** → VTU 的 `flushPromises` 永久挂起、测试卡死且不报错。必须写 `vi.useFakeTimers({ toFake: ['setTimeout', 'clearTimeout'] })`，并在 `afterEach` 里 `vi.useRealTimers()`
- **PowerShell 5.1 没有 `??`** —— 空值合并直接 `ParserError`；另外往 shell 传中文路径/中文字符串会掉编码，定位文件一律用 glob/read 工具拿绝对路径
- ⚠️ **`Select-Object -First` 会制造「假失败」（10-04 踩到，与上面第一条互为镜像）**
  第 132 行说「不能过滤后宣称通过」。这次撞上**反面**：为了省事把测试输出管进
  `pnpm -r run test 2>&1 | Select-String -Pattern "FAIL |failed" | Select-Object -First 4`，
  拿到 `TEST=-1`，看起来像测试挂了。实际重跑落盘后是 **`EXIT=0`、77 个文件全过**。
  原因：`Select-Object -First N` 拿够 N 行就**终止管道**，上游 `pnpm` 被杀 → `$LASTEXITCODE` 报 `-1`。
  两条纪律合起来是：
  - 判定**通过** → 不要过滤，直接看 `$LASTEXITCODE`
  - 判定**失败** → 过滤出来的 `-1` 可能是管道 killsignal，**必须落盘重跑确认**（`pnpm ... *> log` 再读 log）
  - 另外：过滤 `failed` 会命中测试**故意**走的失败路径（core 测握手超时打 `[svc] handshake failed`、
    client 测 500/400 打 `[command] xxx failed: 500`）。**这些 ERROR 行不是失败**，别被它们带着走。

### 5.4 架构约定（下一个人别破坏）

- **`ServiceManager` 不知道插件存在**。过滤以可选参数 `allowedServiceIds?` 从外面传进去，不传即全启。反例写在 `docs/开发计划.html` 风险台账里：过滤一旦写进 `ServiceManager` 内部，`manager.test.ts` 那两处「临时目录 + 假服务」会静默变成零服务启动
- **一个动作的判定只放一处**。三态降级只在 `allowedServiceIds()` 判断；`ServiceManager` 只看到「一个集合或没有」
- **「降级」不等于「回退到假数据」**。原方案「拉取失败回退到内置最小清单」是**错的且有害** —— 内置清单就是第二真源
- **归属是意图，落 `plugin.json`；状态是事实，由 Core 派生**。前端只显示不重算
- **`capabilities[]` 不参与任何判定** —— 一旦被依赖就变成第二个真源
- **依赖满足 = 已安装**，不是「已健康」。**依赖传播 degraded 是刻意不做**的
- **改预设端点 = 写同 id 的 `vendorOverride`**（`buildVendorInstances` 里 `byId` 是 Map，后写覆盖先写）。**但没配凭证的云厂商不能这么改** —— `instanceFromOverride` 会返回 `null`，那条 override 压根不会成为实例，填了也白填

## 8. 交接 checklist

接手的人请按这个顺序确认：

1. 读 `docs/开发计划.html` 的「S7 收口」节 —— 知道系统现在是什么样
2. 读本文第 5 节 —— 知道哪些坑已经踩过、别再踩
3. 跑一遍第 6 节的四条命令 —— 确认基线是绿的（**落盘跑，别过滤**，见 5.3 的假失败）
4. **`git status --porcelain` + `git fetch` 亲自核实一遍本文第 1 节的现状表** —— 尤其「工作区」那一行，它是**快照不是事实**（4.1 #9）
5. 要动插件相关代码，先读第 5.4 节的架构约定
6. 动过任何 `service.json` 就重启 Core，并按第 6 节末尾的 reannounce 三条复验（见 4.1 #7）
7. 要改模型配置页，先确认 4.1 #8 的参考稿能不能找回 —— **它已经丢了**
8. 认领一项第 4 节的事，或开新的
