## 依赖关系

```
P1a ─► P1b ─► P2 ─► P3 ─► P4 ─► P5 ─► P6 ─► P7 ─► P8
```

- **P3（Loop）是 P5-P7 的宿主**：角色 / 技能 / MCP 都挂在它上面。
- **P2 原按能力位拆成 6 个 LLM 插件**（llm 主位 + 3×provider + credentials + llm-retry，各自独立服务进程）；
  **该形态已被 S7 取代**：provider 收敛为**一个** `llm-provider-openai` 进程承载 12 家厂商预设，
  插件层重新划为 **5 个插件 / 6 个服务**（见 `S-对话界面与插件重构-计划.md`） + 模型目录 + 管理 Pane，不重写骨架。
- **P1-P4 = 基座**（2026-09-23 评估定案；P2 于 2026-09-28 修订为能力位拆分，**该形态又被 S7 取代** —— provider 收敛进一个进程、插件重划为 5 个）：P1a 补 2 处小补强；P1b 加通用组件库；P3 加会话存储；P4 加凭证 store + 设置 Pane——各阶段扩展 30~50%，周期已相应上调（见总览）。
- **P4 目标 2026-10-02 修订**（原「多 provider 管理」→「最小可用 agent」）：用户要的是「P4 阶段能有一个简单 agent」（会话管理 / 流式 / 输入框 / 发送按钮 / 模型选择 / 思考强度 / 工具调用 / provider 配置可写死）。审查发现后端链路早已跑通，**断的是前端挂载与参数回传两处接缝**，故 P4 追加「对话工作台参数链路」并吸收原 P4b：把 `llm.models.list` 接到模型下拉、`loop.run` 扩 `provider?/model?/thinking?` 一路落到各家 wire。**工具调用循环仍属 P7**（P4 不越界）。决策与外部参照（pi / pi-gui / Paseo）见 [`P4b-对话工作台-交接.md`](./P4b-对话工作台-交接.md) §0.1。
