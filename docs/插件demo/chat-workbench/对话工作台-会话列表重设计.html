0为什么要重做：现状的七个断层

现在的 SessionListView.vue 是一个 <Card title="会话">：工具条三个按钮， 下面一个 <List>，行里只有标题 + toLocaleString() 全时间戳 + 一个 ⚠。 它在一个 240px 宽的侧栏盒子里，会话一多就不好用了。具体是这七处：

断层现状后果 / 本次改法
① 没有运行态 sending 是每个 iframe 各自的本地派生量，只回答「我这个盒子在跑吗」 三个盒子都开着时，你无法知道是哪个会话在跑。而 loop.state.changed 明确带了 sessionId —— 数据早就在事件里，列表只是没画。→ §4 运行态圆点
② 重命名/删除打的是「当前会话」 工具条的按钮读 currentMeta，与行上的点击无关 点第 7 行、删掉的却是正在看的那条。→ 行内就地改名 + 行内菜单，作用对象永远是它自己那一行（§3 / §7）
③ 平铺无分组 一个 List，只有 updatedAt desc 一档 20 个会话之后要找昨天那条只能靠滚。→ 时间桶分组（§2）。天枢分 workspace，ost 没这字段， 所以换时间轴；分组键留在 §12 待决
④ 时间戳是全量格式 new Date(iso).toLocaleString() 一行放不下，横向溢出把标题挤没。→ 相对时间（刚刚 / N 分钟前 / 昨天 / M/D），hover 才让位给操作按钮
⑤ 没有搜索 — → 头部开关式搜索，搜索时强制展开全部分组（§6）
⑥ 零键盘可达 行是普通 div，不可聚焦、无 role → listbox 语义 + 漫游 tabindex + ↑↓/Enter/Delete//·⌘K/Esc（§7）
⑦ 空态只有一个 零会话时有 EmptyState，搜索无结果时是一句裸文字 → 区分「还没有会话」（给动作）/「无匹配」（给退路），归档桶另有自己的空态（§6）
没有被改的。三视图的协议契约一个字没动：仍然是同源 SSE 各自订阅、 只有 curId 走 sessionStorage 跨 iframe 共享 （state/session-sync.ts）。本次只是把同一个 curId 的那一侧画得更像一个侧栏， 以及让每个 iframe 能从 loop.* 推出任意会话的状态而不只是当前会话的。

2分组骨架

五行，按这个顺序固定：置顶 → 今天 → 昨天 → 本周 → 更早。置顶行在所有桶之上单独成组 （它同时也是拖拽的禁区边界，§5）。桶本身可折叠，折叠状态是本视图的本地偏好。

为什么按时间而不是按项目。天枢按 session.workspace 分组，因为它本来就是 「一个工作区 = 一个 git 仓库 = 一个项目」的形态。ost 的会话是纯 append-only 文件， SessionMeta 里没有 workspace / project 任何字段（§12）。硬造一个「项目」概念要动协议与存储， 而时间桶零成本、且恰好解决 240px 侧栏的真实痛点（要找昨天那条）。 真要项目分组，加一个可选的 group?: string 字段即可，本文件的桶函数是唯一改动点。

4运行态圆点

这是本次重设计最核心的一处新增。它不需要任何新事件： loop.* 每一条都带 sessionId，只是现在没人拿它画东西。 做法照抄天枢 features/character-presence/motion.ts 的思路 —— 纯函数投影：一串 run 事件 → 一个 motion 枚举 → 一组 CSS 类。不引入新的组件库依赖。

运行态圆点 点右下「◍」切到运行中场景：四个会话同时处于四种不同 motion 脉动频率 = 紧急度

5排序与拖拽

排序规则照抄天枢 stores/sessionListPrefs.ts 的 orderSessionRows()， 改成四档。它之所以值得抄，是因为它把「用户的手动排序」和「系统的时间排序」分成了两层， 新会话不会因为你不认识它而把别人的位置挤掉。

1. 置顶簇整体在前 ← 唯一的全局档位 2. 簇内 updatedAt desc，id 兜底 ← 确定性的，防同刻并列 3. 手动顺序在「各簇内部分别」套用 ← 所以拖不动的置顶行不挡未置顶行的排序 4. 不在手动顺序里的行浮到本簇顶部，彼此仍按 recency

拖拽：能做什么、不能做什么

拖拽重排 按住「SSE 重连后 loop.run 落空」往上拖 —— 蓝线是插入位 同分区内 · 同置顶性
动作允许？规则与理由
同分区内、两个都未置顶的行之间重排是 写入 localStorage 的 order[bucket]，只对本桶生效
跨时间桶拖（今天 → 更早）否 桶是时间事实，不是用户的分类。允许拖就等于允许谎报时间
拖到置顶组否 置顶有独立语义与独立档位。想置顶请用菜单里的「置顶」——那是意图，拖拽是顺序
已归档行否归档桶内部纯按时间排，不接受手动顺序
搜索态下拖拽否 屏幕上显示的是过滤结果，落盘却是全量顺序 —— 按看到的东西排序会存下错误的顺序
被拒绝的四种情况都没有提示。这是抄天枢的一个已知缺陷：rowDragProps() 静默 return {}，用户拖了一下什么也没发生，只能猜。这里补一条：拖拽被拒时给 toast 说明原因 （host.toast('不能在时间分组之间拖拽')），成本一行。

8② 对话时间线

时间线本身结构不用大改（思考块 / 工具卡 / 停因用量都是现状已有的），但有两件事要跟着列表一起改， 否则两侧对不上：

  1. 它得知道「当前这一轮在干什么」。现在 ② 里的 spinner 只挂在「本轮在跑 + 这一行正在流式」这一种情况上； 列表已经把 motion 算出来了，② 应该用同一个 motion 点，于是侧栏那 7px 和时间线上的状态是同一件事的同一份投影。
  2. 它得能显示「别的会话出错」。切走以后那一轮失败了，回来要看得见失败摘要， 而不是一段没有尾巴的文本。
② widget.chat-timeline 流式中：思考块折叠、工具卡执行中、正文尾光标、停因与 token 用量 纯展示，从不主动写状态
顺带修一个已经存在的 bug。ChatTimelineView.vue 里用了 --color-accent 和 --color-surface-1， 而 sdk/ui/src/tokens.css 里这两个名字不存在（真名是 --color-primary 与 --color-surface）。后果是：用户气泡没有底色、流式尾光标是透明的。 本 Demo 一律用真名 —— 这也是 tokens-parity.test.ts 那类测试存在的原因： token 名写错，TypeScript 与 CSS 都不会报错。

9③ 输入框

输入框只改一处跟侧栏有关的：「无 provider」空态现在会占满整个盒子， 而它其实是全局配置问题，不该由输入框承担 —— 现在它给了路径（去设置配 API Key）， 这个是对的，保留。真正的改动是 Enter 发送 / Shift+Enter 换行 与 Esc 停止，和侧栏的 Esc 分层不打架。

③ widget.chat-composer Enter 发送 · Shift+Enter 换行 · Esc 停止（本轮在跑时 Esc = loop.cancel，而不是清搜索） 状态全是本地的
请求参数行（provider / 模型 / 思考强度）留在输入框里，不上提到侧栏。 它们是这一轮的参数，不是会话的属性。放进会话标题旁会诱使人以为「这个会话就是这个模型跑的」—— 而实际上每轮都可以换。当前实现把它们留在 ③ 是对的，本 Demo 保留。

10组装与一次发问的走线

重做列表不改变任何进程边界。下面是一次发问在三个 iframe 里的完整走线 —— 注意没有任何一步是「侧栏 → 时间线」的直接调用，全部靠同源 SSE 广播。

用户点「发送」 │ ├─ ③ 发 loop.run{requestId=A, sessionId, text, provider, model, thinking} │ └─ 若没有 curId：③ 先 session.create（curId 在这里被写进 sessionStorage） │ ├────────────── SSE 广播给三个 iframe（都订阅了 loop.* / message.appended） │ ├─ ① 收到 loop.state.changed{running, sessionId} → 该行 motion = thinking │ ② 收到 loop.state.changed{running} → 建 in-flight-A 占位行，caret 亮起 │ ③ 收到 running → sending = true，输入框禁用，出现「停止」 │ ├─ loop.token.streamed{reasoning} → ② 写进 think 块（不是正文） ├─ loop.tool.executed{ok:undefined} → ① 该行 motion = working │ ② 工具卡转 is-run ├─ loop.token.streamed{text} → ① 该行 motion = speaking │ ② 正文累加 + caret ├─ message.appended{assistant} → ① 时间刷新 / 该行跨桶前移 │ ② 删掉占位行，改用历史里的那条 ├─ loop.state.changed{idle} → ① motion = success ② sending=false ③ 输入框解禁 │ └─ 若 loop.run.failed{code} → ① motion = error（红点留住） ② 末尾内联 fail 块，不清上文 ③ 输入框内容原样保留
侧栏在这条链上的位置。它是唯一写 curId 的视图，所以它决定了 「后面两个盒子看哪条会话」；而它自己读的 loop.* 全是广播，于是它知道 每一个会话的状态而不只是当前那条。这是它从「当前会话的属性列表」升级成「会话面板」的关键。
这条链一个字都不用改 —— shared/src/events.ts 里 loop.* 已经带 sessionId 了。

12字段断层：SessionMeta 缺什么

状态（2026-10-07）：下表六项除「项目分组」外均已落地。 pinned+session.pin、archived?+session.archive、 parentId?（子会话树）、lastMessage?（服务端拼预览）、session.export（Markdown 下载）均已实现； 未读点走 sessionStorage；跨会话运行态由 loop.* 投影（无需新字段）。 项目分组（group?）按计划不做（时间桶已覆盖）。下表保留原始决策记录。
能力需要的字段 现状不补会怎样建议

13窄面板退化

默认预设给侧栏 240px，但用户可以在 dockview 里把它拖到很窄（右侧那条竖分割线可以拖到 0）。 240px 是默认，不是下限。三层退化，按可用宽度切：

宽度丢掉怎么丢剩下的仍然能用
≥ 220px—完整形态分组 / 预览 / 时间 / 悬停操作 / 拖拽
176–220px预览行一栏一关（不是自动的：用户自己决定要不要那一行） 点「▤ 预览」关掉即可
< 176px预览行 + 时间 + 分组名计数@container 查询自动降级 点 + 上下键 + 菜单仍在 —— 列表永远可操作

宽面板下侧栏可以做的事，窄面板下一个都不能少：新建、选中、改名、删除。 时间戳和预览是锦上添花，可被裁掉；可操作性不是。

实现建议：给 .rail 上 container-type: inline-size， 退化阈值用 @container (max-width: 220px) 而不是媒体查询 —— 侧栏宽度取决于用户在 dockview 里怎么拖，跟视口宽度没关系。这一点与 tool_manager 的 .tools-view 是同一个理由。

  • 留：时间桶分组、运行态圆点、行内操作、未读点、相对时间、就地改名、键盘、窄栏退化。
