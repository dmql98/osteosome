一句话：五个插件不是五套设计，是同一条「能力位」范式的五个实例。 本计划把 docs/插件demo/ 下的工具管理、皮肤管理、对话工作台、技能管理、智能体角色五份稿 收成一条统一顺序 —— 从「阶段 0 全量确认」开始，不把任何「已完成」当作已验证；再冻结决策与共享契约，按「角色 → 技能 → 工具 → 皮肤」推进，对话工作台止血并行。
起点是阶段 0：Core 与工作台（client 壳 + plugins/workbench）逐模块从头核对、列出优化项 —— 它们承载后面所有插件，必须先确认再往上盖。里程碑追踪里的 P1a–P4 / S0–S8 在本计划里只算「声称完成」，逐项确认后才计入基线。
判据贯穿全篇：能力住在服务进程里、一个收集命令 + 一个重播事件、owner 独占写自己的 dataDir、 缺失是合法的、顺序必须确定、失败也要产结果、写只限自己且 Core 不解释 payload。
本计划不新增协议机制：所有新 topic 都是 shared/src/events.ts 的 EventMap / CommandMap 上的新行。

「缺失是合法的」让依赖不是硬阻塞。 每个插件都能单独装上并降级工作：没装 tools 插件 → 模型没有文件工具，对话照常；没装 agents → composer 角色下拉消失、回落裸会话； 没装 skills → 技能索引片段为空。所以顺序由价值与可观测性决定，而不是由编译依赖决定。

2共同范式：五个插件共享的七条纪律

这是「整体看」最重要的结论 —— 每份稿都在重复同一条纪律。落在实现上就是 docs/插件标准.html。

#纪律怎么守破坏后的症状
1能力位 = 独立服务进程 装插件 = 多起进程；卸载 = 能力消失，不是报错。Core 只启「已安装插件声明的服务」。 卸了插件但模型还假装拥有能力；或没装插件整个应用不可用（S7 差点 bricking 的坑）。
2一个收集命令 + 一个重播事件 xxx.list（收集方上线问一次）+ xxx.state（owner 每次变更重播整份）。订阅方只写一行订阅就拿到全量。 晚启动的订阅方永远看不到目录（provider 那个坑，已踩过两次）。
3owner 独占写自己的 dataDir 握手发的 dataDir 指向 pluginDataDir(dataDir, pluginId)，服务直接 fs 读写；跨插件只读别人的事件。 两个真源；「数据目录必须有主人」被打破（凭证插件退休的教训）。
4缺失是合法的 未注册工具 / 技能 / 皮肤 / 角色 → 忽略 + 标一条悬空引用，不报错、不阻止保存。 用户把可选插件卸了，对话直接不可用；或界面显示「无效」逼用户重装。
5顺序必须确定 目录排序键 serviceId → name；策略 map 按 key 渲染；落盘按码位。 顺序抖动 → prompt 缓存整片失效 → token 费用翻十倍，且零报错。
6失败也要产结果 被拒 / 超时 / 禁用 / 未知工具，四种都发 ok:false + 人话原因，让模型自我纠正。 模型一直转圈（静默丢弃的等价物）；或把失败当成功。
7写只限自己 + Core 不解释 payload 本插件只写 ${dataDir}/；Core 只做「查白名单 + 搬字节 + 记生命周期」。 Core 被迫理解 characters.json / 皮肤语义 → 破「不解析插件内容」这条不变式。
同构复刻的清单（不新增插件交互方式）： llm.provider.reannounce · models.prefs.state · tools.state · skills.state · skin.state · agent.state —— 全部是「收集命令 + 重播事件」的同一套机制。

测试跟着被测物走

  • 纯函数（约束引擎 / 路径守卫 / 匹配器）留在 shared，跨进程拆分后一条不用改。
  • 协议落在各执行者包；端到端留在 core/tests。
  • 集成冒烟必须串行（fileParallelism:false）—— 每个冒烟拉起真 Core + 多服务（≈36 进程），并行会挤破握手预算导致假红。

四类必须存在的测试

  • 故障注入（P1）：在 renameSync 前抛错 → 目录里是完整旧文件或完整新文件，不允许都没有。
  • kill -9 集成（P7）：本地测试走优雅停机，看不到「残留注册」；必须真 kill。
  • 字节稳定性：同一输入两次调用，tool.execute.result.content 与目录数组字节级一致（prompt 缓存）。
  • 幂等：同一 T 收到两条 tool.approval.resolved，只生效一条（防副作用跑两遍）。

手工 e2e（P7，每条能眼睛验）

  • 绑真实项目目录 → 发「列出文件」→ 摘要里是真实文件名。
  • 写类工具弹审批；只读不弹；越界触发工作区审批并批准后重派成功。
  • kill -9 shell-tools → tools.state 少 bash/pwsh，其余照常。

10一句话纪律（贯穿全程）

先确认基座，再往上盖（Core 与工作台逐模块核对，不信任「已完成」）；
先让服务能各自工作，再切主线；每个执行者是一个目录（可独立删）；
越界与副作用各走各的闸（约束不弹窗、审批才放行）；
loop 手里不留路径；能力住在服务里、不住在插件清单里；
拥有用户数据的插件，卸载保留、重装即恢复。
